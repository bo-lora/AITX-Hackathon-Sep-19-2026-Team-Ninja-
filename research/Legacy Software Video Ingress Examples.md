# **Video Ingress and Translation Protocols for Legacy Software Automation: A Product and Architecture Definition**

## **The Legacy Translation Bottleneck and the User Experience**

The modern software ecosystem is characterized by a fundamental disconnect between cutting-edge, API-driven artificial intelligence clients and the graphical user interface (GUI)-bound legacy applications that power core enterprise operations. Millions of knowledge workers rely on older-school desktop software that is entirely non-addressable by modern AI agents. The central challenge lies in workflow translation. A professional user possesses a highly functional, practiced workflow within a legacy application, but that workflow cannot be directly executed, understood, or triggered by the AI clients the user prefers for their broader productivity tasks.  
To resolve this friction, this product introduces a video-first ingress pipeline that acts as a deterministic translation bridge. The user experience is anchored by a specific persona, representing the target end-user who is frustrated by a repetitive, daily task embedded within legacy software. The operational flow dictates that the user simply records themselves performing the task on their screen. The recording surface or software utilized for capture is irrelevant to the pipeline, so long as it produces a standard video file.  
The user opens the bridge application, uploads the raw video file, provides a brief contextual description of the task, and initiates the processing pipeline. The application then returns a structured, copy-paste artifact. The user seamlessly pastes this artifact into their preferred AI client, whether that is Cursor, ChatGPT, or Grok. The choice of terminal client remains entirely with the user, decoupling the automation from any single proprietary AI ecosystem.  
The core directive of this pipeline is the elimination of repetitive manual navigation. The user should never have to manually click through every screen of the legacy software again. By leveraging the uploaded video as the sole ingress point, the system observes the human operator to deduce the necessary sequence of actions, the required data schemas, and the logical decision trees. The resulting artifact empowers the AI client to execute the workflow autonomously, transforming a rigid legacy application into an AI-addressable service.

## **System Architecture and the Reuse-Versus-Build Strategy**

Given the strict four-hour time constraint inherent in the hackathon development cycle, the technical strategy must aggressively prioritize the integration of existing, open-source infrastructure over novel foundational builds. The objective is to construct a continuous pipeline that successfully bridges a video file to an executable payload without exhausting development hours on solved problems in media processing or protocol formatting.  
The architecture divides the pipeline into distinct operational stages: media ingestion, state extraction, semantic mapping, and payload generation. By identifying which components can be procured from the open-source ecosystem and which require bespoke heuristic logic, the team can efficiently allocate engineering resources.  
The media ingestion and extraction stages will rely entirely on established utilities. For processing public tutorial videos, the system will integrate yt-dlp, a robust command-line tool capable of extracting audio, video, and native subtitles from thousands of sites16. For local, user-uploaded video files, the system will utilize FFmpeg, the standard command-line utility for processing media, to handle demuxing, audio extraction, and visual sampling16. The transcription of the audio track will be handled by Faster-Whisper, a highly optimized implementation of OpenAI's Whisper model that offers rapid transcription speeds and minimal memory overhead, allowing for local execution without relying on high-latency cloud APIs16.  
The payload generation stage will leverage the official Model Context Protocol (MCP) software development kits. Rather than constructing a custom JSON-RPC implementation from scratch, the team will utilize the official Python SDK, specifically employing the FastMCP framework19. This framework allows developers to define Python functions and automatically generates the compliant JSON schemas and standard input/output (stdio) transport layers required by the protocol20.  
The primary "build" effort will be focused entirely on the heuristic translation engine. This bespoke middleware must take the timestamped text output from Faster-Whisper and the visual keyframes generated by FFmpeg, align them temporally, and deduce the logical sequence of UI interactions required to complete the legacy task. This logic is the core intellectual property of the bridge application, serving as the critical link between unstructured video observation and structured protocol generation.

## **Video Processing and Visual State Extraction**

To transform an unstructured video file into a structured artifact, the architecture must first execute a rigorous feature extraction pipeline. This stage isolates the audio and visual components of the video, mapping the temporal sequence of the user's legacy software workflow.  
The audio track of a screen recording provides the semantic context for the visual actions. A user will typically narrate their actions, providing explicit labels for the UI elements they interact with. The pipeline utilizes FFmpeg to demux the audio from the video container and passes it to the Faster-Whisper engine16. The transcription process utilizes models like base or small for balanced speed and accuracy, generating a JSON or SubRip Subtitle (SRT) file that intrinsically links the extracted text to precise temporal timestamps16.  
To handle hallucinations—instances where the speech-to-text model generates text during periods of silence, background noise, or high-intensity game audio—Voice Activation Detection (VAD) is implemented to ensure that only true speech is passed to the transcription engine22. This timestamped transcript serves as the foundational timeline for the workflow.  
Simultaneously, the visual track provides the spatial mapping of the legacy software's UI state. Running expensive computer vision models on every frame of a video is computationally prohibitive and unnecessary23. Instead, the pipeline utilizes FFmpeg's scene change detection and keyframe extraction capabilities to isolate the exact moments where the UI undergoes a significant state change, such as a new dialog box appearing or a different tab being selected.  
The extraction utilizes FFmpeg filters to isolate Intra-coded frames (I-frames) or detect scene changes based on visual variance. Combining a scene filter with a showinfo filter allows for precise scene change detection anchored to explicit timecodes24. By cross-referencing the timecodes of the extracted visual keyframes with the timestamps of the Whisper-generated transcript, the pipeline constructs a perfectly aligned sequence of states. If the transcript dictates a specific menu selection at a distinct timestamp, and a new visual keyframe showing that menu is detected concurrently, the system successfully maps the semantic instruction to the visual consequence.

## **Visual Action Mapping and Vision-DOM Alignment**

Once the video is distilled into an aligned sequence of timestamped text and visual keyframes, the system must bridge the gap between observation and automation. The legacy software workflow must be translated into an actionable script that an AI agent can execute.  
The principles required for this stage borrow heavily from modern web automation frameworks designed for AI agents, specifically open-source libraries like browser-use. In standard web environments, these tools enable AI agents to autonomously navigate browsers by observing the Document Object Model (DOM), determining a plan, and executing actions via headless controllers like Playwright25. The dynamic feedback loop mimics human browsing, evaluating the parsed DOM to confirm whether an expected element appeared or if a form was successfully submitted25.  
However, legacy software inherently lacks a readable DOM. The applications present as opaque visual canvases to traditional automation scripts. To overcome this, the bridge application adapts the browser-use methodology for static keyframes27. The system utilizes advanced Vision-Language Models to analyze the extracted keyframes and generate pseudo-DOMs or spatial maps of the legacy UI. By applying bounding boxes to UI elements—such as buttons, text fields, and dropdowns—visible in the keyframes, the system builds an interaction map that correlates with the semantic instructions extracted from the audio transcript.  
The output of this stage is a generalized action sequence that abstracts away fragile pixel coordinates in favor of logical steps. For example, in a municipal cashiering workflow, the generated sequence defines the logical progression of locating the payment menu, targeting specific input fields for the case number and amount, and interacting with the confirmation button8. This resilient, logical sequence forms the foundation of the tool that will be exposed to the final AI client, ensuring the automation can survive minor UI updates or screen resolution changes.

## **Payload Generation: The Model Context Protocol (MCP)**

The defining innovation of this product, and the ultimate output delivered to the user, is the Model Context Protocol (MCP) payload. The user requires a copy-paste artifact that seamlessly integrates into their existing AI environment, granting that specific AI the capability to interface with the legacy software without requiring the user to engage with proprietary automation dashboards.  
The Model Context Protocol is an open-source standard, initially introduced by Anthropic and further expanded by GitHub, that defines how AI systems discover capabilities, exchange structured context, and execute actions through external tools and services28. MCP acts as a universal interface, replacing the need for bespoke API integrations by standardizing communication via JSON-RPC 2.0 messages28. The architecture supports stateful, two-way connections across standard input/output (stdio) or streamable HTTP, allowing the AI model to maintain context across extended sessions28.  
The bridge application transfigures the extracted legacy workflow into an operational MCP Server. This server exposes specific building blocks to the MCP Client (such as Cursor, Claude Desktop, or VS Code), fundamentally categorized as Tools, Resources, and Prompts28.  
Tools are the action layer within MCP, representing predefined, executable functions that the AI model can invoke to interact with the legacy software28. Each tool must be defined by a strict JSON Schema that explicitly outlines its name, a human-readable description, and the required input parameters29.

| MCP Tool Component | JSON Schema Implementation (e.g., Tyler Tech Outreach Docket) | Protocol Purpose |
| :---- | :---- | :---- |
| name | update\_outreach\_docket | Identifies the tool uniquely within the MCP server namespace20. |
| description | Automates the updating of a municipal court case file for outreach dockets based on the observed legacy workflow. | Provides semantic context allowing the AI client to understand when to invoke the tool29. |
| inputSchema | type: object | Dictates the structured format required for the JSON-RPC request31. |
| properties | case\_number (string), appearance\_status (string), fine\_amount (number) | Defines the exact data points the AI must extract from the user's prompt28. |
| required | \["case\_number", "appearance\_status"\] | Enforces validation before the tool call is executed20. |

When the user pastes this generated MCP configuration into their AI client, the client immediately discovers the new capability. If the user commands the AI to update a specific court case, the AI evaluates the JSON Schema, constructs a valid parameter payload, and sends a tools/call message to the MCP server20. The server then executes the spatial automation sequence mapped in the previous stage.  
Additionally, the payload can define Resources, which provide read-only datasets identified by URIs to supply the AI with essential context, and Prompts, which are reusable templates that guide the AI in utilizing the newly generated tools efficiently28. This comprehensive payload completely abstracts the legacy application, translating it into a native extension of the AI client.

## **Provenance, Traceability, and Quality Assurance**

A non-negotiable constraint of this hackathon product is absolute traceability. The generated MCP artifact must accurately reflect the original video ingress without introducing hidden manipulations, silent extra sources, or hallucinations. In enterprise environments such as municipal courts or financial accounting, an automation tool that cannot definitively prove why it took an action introduces unacceptable risk. The presented product must be exactly what it claims to be, necessitating a robust Quality Assurance (QA) and Inspector loop.  
Because the translation pipeline relies on probabilistic models (like Whisper and Vision-Language Models) to map states and generate schemas, there is an inherent risk of generative drift. To mitigate this, the architecture leverages the developer-first design of the Model Context Protocol itself. MCP is heavily optimized for observability, providing structured logs, predictable debugging, and explicit error codes29.  
Furthermore, the protocol mandates strict security and user consent guidelines. Because tools represent arbitrary code execution, descriptions of tool behavior must be considered untrusted until verified30. Hosts must obtain explicit user consent before exposing user data or invoking any tool, ensuring the user understands what the tool does before authorizing its use30.  
The bridge application enforces traceability by establishing a deterministic link between the final MCP JSON Schema and the raw ingress data. By retaining a side-by-side mapping of the original video keyframe, the specific timestamped transcript segment, and the generated tool parameter, the QA Inspector can definitively verify the provenance of every automation step. If the transcription model hallucinates a step or attempts to define a tool parameter that does not correspond to a visual element in the extracted keyframe, the discrepancy is immediately flagged, and the schema generation is halted. This visual inspection process guarantees zero false positives or false negatives in the workflow translation, ensuring the final copy-paste payload is safe, verifiable, and strictly bound to the user's recorded intent.

## **Strategic Deployment and Hackathon Deliverables**

The ultimate objective of this four-hour development sprint is the delivery of a fully runnable slice of the bridge application that satisfies the core user experience narrative. By strictly adhering to the reuse-versus-build strategy, the team avoids the pitfalls of attempting to construct redundant media processing pipelines or custom communication protocols.  
The integration of FFmpeg for temporal and spatial extraction, Faster-Whisper for localized semantic mapping, and the FastMCP SDK for standardized payload generation creates a highly scalable, deterministic translation bridge. The frontend execution focuses entirely on the user journey: uploading a video of a legacy software task, providing brief context, and receiving a verifiable, traced MCP payload.  
By converting a rigid, click-heavy legacy interface into a fluid, JSON-Schema defined MCP Tool, this application fundamentally alters how knowledge workers interact with non-addressable software. The user is no longer constrained by the graphical user interfaces of Tyler Incode, QuickBooks Desktop, or specialized industrial hardware controllers. Instead, they interact with their legacy systems entirely through the conversational interface of their chosen AI client, executing complex, repetitive workflows with unprecedented speed, accuracy, and traceability.
